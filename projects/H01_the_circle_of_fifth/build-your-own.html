Build Your Own Chart

This is the file the whole series was aimed at. You noticed something real:

"There are so many elaborate charts built out of the circle of fifths, and most of the complicated ones seem to be worth the most only to the person who built them."

That intuition is correct, and file 08 explained why. Now we turn it into a method — so instead of collecting other people's diagrams, you build the minimal one that serves a question you keep asking.

1. Why a personal chart is "overfit"​

A chart is an index: a data structure that makes some lookups cheap by committing to a layout. Every index is built for a query pattern — the set of questions its author actually asks. A dense, custom chart encodes:

  1. which relationships its author cares about (fifths? thirds? shared tones? scale-degree function?), and
  2. which queries they run often enough to want pre-computed.

Hand that chart to someone with a different query pattern and it reads slowly — its layout optimizes lookups they never make, while burying theirs. That's not a defect; it's the nature of an index. The value of a chart is proportional to how well its adjacency matches the reader's most frequent question. So a great personal chart is supposed to be somewhat useless to others.

The practical corollary: stop collecting charts, and start naming your query.

2. The four-step method​

1. NAME the recurring query.
     The thing you actually look up mid-writing or mid-practice.
     e.g. "what can I modulate to from here?"
          "what are my reharm options for this chord?"
          "how bright/dark is this mode vs. that one?"

2. IDENTIFY the relationship that answers it.
     fifth-distance? shared-tones? third-relations? function? brightness?

3. CHOOSE the projection whose ADJACENCY equals that relationship.
     Put the thing you query most on the axis that's easiest to read
     (a line, a ring, a small grid). Adjacency should mean "answer."

4. PRUNE ruthlessly.
     Every extra ring, color, or label is index bloat. Keep it ONLY if it
     serves a query you actually run. If you never ask it, don't draw it.

Step 4 is the one people skip, and it's why most homemade charts collapse under their own weight: they keep adding dimensions "for completeness" until the chart answers everything slowly and nothing quickly.

3. Worked example A: the modal brightness line​

Query: "How bright or dark is this mode, and what's one notch brighter?"

Relationship: brightness = the sharp/flat gradient (file 03), which is fifth-order. So the right projection isn't a wheel at all — it's the circle cut and straightened into a line:

brighter  ←────────────────────────────────────────────→  darker
 Lydian   Ionian  Mixolydian  Dorian  Aeolian  Phrygian  Locrian
  (#4)    (major)   (b7)       (b3,b7) (nat min) (b2...)   (b2,b5)

Each step flattens exactly one degree. This "chart" is a one-dimensional projection — it throws away everything the circle knew about keys and function, because the query didn't ask for them. For "how bright is this mode," a line beats the full wheel. That's a feature.

4. Worked example B: a reharm wheel​

Query: "Given this dominant chord, what are my substitution options?"

Relationships that answer it: the antipode (tritone sub, file 07) and the one-slot-clockwise neighbor (secondary-dominant chains). So keep the ordinary circle of fifths but annotate only those two moves — draw the tritone axis through your chord and mark its clockwise neighbor. Everything else on the wheel stays un-inked, because your query never touches it. The result is the circle of fifths plus two arrows — not a new baroque diagram.

5. Worked example C: a modulation-distance ruler​

Query: "How far is a jump to that key, and do I have a pivot?"

Relationship: circle-step distance = shared-note count = pivot availability (file 06). The minimal chart is a ruler: mark your home key at 0 and label each step outward with (steps, shared notes, feel). You've compressed the whole modulation file into a one-line lookup — because that's the only query the ruler needs to serve.

6. When a complex chart is worth building​

Elaboration pays off in exactly the cases where the query pattern is shared or repeated, so the up-front layout cost amortizes:

  • Pedagogy — a chart used by many students runs many people's (similar) queries; complexity that would be overfit for one person is justified across a cohort.
  • A specific compositional system — the Coltrane circle (file 08) is elaborate and worth it, but only to music that actually runs major-third symmetry. It's the honest example of a chart that's near-useless outside its query.
  • Algorithms — the spiral array earns its third dimension because a key-finding program queries spelling millions of times.

Outside those, prefer the smallest chart that answers your question. Complexity is a cost you pay on every read, not a virtue.

7. The whole series in one sentence​

The circle of fifths is a projection that makes key-distance and function cheap to read; mastery is not memorizing charts but knowing which relationship each chart makes cheap — and being able to build the minimal one for the question you keep asking.

If you can look at any harmonic diagram and immediately ask "what query is this an index for, and is it mine?" — you've got the whole point, and the rest is lookup.
